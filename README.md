# Data and code for "Tree-preconditioned GMRES for the multiple scattering equations of photoelectron diffraction"

Authors: Mohammed Benaissa, Keisuke Hatada, Didier Sébilleau.
Archived release: <DOI to be filled>. Paper: <to be filled after acceptance>.

This record holds the solver, the run scripts, the raw results of every run in the paper and the scripts that turn
them into the numbers, tables and figures. It does not contain the paper text.

## Contents

| Folder or file | What it is |
|---|---|
| `code/msspec_gmres/` | Modified copy of MsSpec. The GMRES solver and the spanning-tree preconditioner are in `src/msspec/spec/fortran/phd_gm_noso_nosp_nosym/axb_mat_ms_la.f`; the Python switch is `algorithm='gmres'` in `src/msspec/calculator.py`. |
| `code/runners/` | `run_set.py` runs one set of cases and writes one folder per run; `worker.py` is the single-run process. |
| `code/tests/` | Regression test (`test_tree_gmres.py`), a check on Ag, Ni and Cu against dense LU (`material_check.py`) and the build manifest writer. |
| `code/examples/gmres_ped_cu.py` | Smallest complete example of a GMRES calculation (Listing S4 of the paper). |
| `code/BUILD.md`, `code/rebuild.sh`, `code/BUILD_MANIFEST.json` | How to build the Fortran extensions, and the source and binary hashes, compiler and BLAS link of the build that made the results. |
| `platform/` | Case selection: the 100 test cases (`materials_100.csv`, `materials_v2.csv`, `e17_cases.csv`, `materials_big.csv`), the spectral-radius probe (`rho_probe.py`) and the selection scripts. |
| `data/inputs/` | Benchmark input tables. |
| `runs/<set>/rows.csv` | One row per run: accuracy-relevant settings, steps, wall time, peak memory, status, load average, source hash. |
| `runs/<set>/<case>/<method>_<rep>/` | `row.json` (the same row) and `result.npz` (arrays `theta`, `phi`, `cross_section`, `direct_signal`). |
| `analysis/` | `evaluate.py` (error metrics), `stats.py`, `make_results_numbers.py`, `plot_*.py`. `analysis/out/` holds the derived tables. |
| `figures/` | The figures of the paper (PNG and PDF). |
| `manuscript/numbers*.tex` | The numbers used in the paper, generated by `analysis/make_*numbers.py`. |
| `PROTOCOL.md`, `DEVIATIONS.md`, `GRMES_MODULES.md` | Protocol of the study, dated changes to it, and a walk-through of the solver modules. |

Run sets used in the paper: `p100` (main test set: dense LU, GMRES at tolerance 1e-2, series orders 1 to 3), `p100_tol3`,
`p100_tol6` (tolerances 1e-3 and 1e-6) and their cap-67 and cap-100 reruns, `p100_steps` (GMRES stopped after 1 to 6 steps),
`p100_e3` and `p100_e3_dump` (residual against error), `nopre_*` (no-preconditioner comparison), `series4`, `big*`,
`e16_*` and `maps_e16*` (four larger clusters, stereographic maps), `e17_*` (energy scans and their timing).

## Reproduce

1. Build (needs Python, gfortran, LAPACK/BLAS; versions are in `code/BUILD.md`):
   ```
   cd code
   python3 -m venv _venv && source _venv/bin/activate && pip install numpy scipy ase
   ./rebuild.sh
   PYTHONPATH=msspec_gmres/src python tests/test_tree_gmres.py     # expects PASS
   ```
2. Re-make the numbers and figures from the saved results (no solver run needed), from the top folder:
   ```
   python analysis/make_results_numbers.py
   python analysis/plot_p100_results.py
   ```
   The result is the same as the numbers in `manuscript/` except six `Pert*` macros of a private sensitivity check, which are skipped. The other `analysis/plot_*.py` scripts work the same way; each one names the run sets it reads in its first lines.
3. Re-run a set of cases (hours; one process at a time, 8 threads; see `PROTOCOL.md` section 1 for the machine):
   ```
   cd code
   python runners/run_set.py --set <name> --mat-ids <ids> --methods gmres --scan theta:-90:89:180 --tol 1e-2 --cap 67
   ```
   Cases are listed in `platform/materials_*.csv`. Wall times depend on the machine; the numbers of steps and the errors
   do not.

## Not included

- The run logs (`log.txt`) and the MsSpec working folders (`calc/`) of every run, because of their size (several GB); the
  solver status lines that the paper uses are stored in `rows.csv`.
- Runs that are small tests only (`*_test*`) and the pilot; none of them is cited as a result.
- The compiled `.so` files and the virtual environment: build them with `rebuild.sh`.
- MsSpec itself is the work of its authors (Sébilleau et al., Comput. Phys. Commun. 182, 2567, 2011). Only the changes of this study
  are new; the unchanged parts keep their original licence.
